Chapter 01 上游协作的演化脉络

上游协作并非一蹴而就，而是从 Linux 内核邮件列表时代逐步演化而来。补丁驱动模型确立了改动应回到源头的核心契约，而 Git 与 Pull Request 则让这一理念在当代获得新的生命力。

1991
Linux 内核起点
Linus Torvalds 发布 Linux 内核，通过公开邮件列表接收社区补丁，奠定上游协作的雏形与最初的契约精神。
PATCH-DRIVEN
补丁驱动模型
以邮件列表补丁为核心工作流，提交者将差异贴入公开渠道，天然形成向源头汇聚的单一反馈路径。
CONSENSUS
上游权威共识
社区逐渐形成"改动应回到源头"的默契，避免下游分支碎片化，上游成为质量与合并的最终裁定者。
2008 →
从补丁到 PR
Git 与 GitHub 将补丁协作演进为 Pull Request 模式，可视化讨论、CI 检查与代码审查让协作门槛持续降低。
