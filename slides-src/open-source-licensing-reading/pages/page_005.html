主流许可证速览
OPEN SOURCE LICENSE COMPARISON
阅读方法 重点关注三列——是否强制开源是否含专利授权是否允许闭源链接，这三点几乎决定了 90% 的选型场景。以下六款协议覆盖了从"近乎公共领域"到"强 Copyleft 传染"的主流选择。
许可证名称 核心约束 开源强制性 闭源链接 专利条款 适用场景 / 一句话结论
MIT 协议
仅署名 / 允许闭源商用
 仅要求保留版权声明；允许商用、闭源、修改。是约束最少的主流协议。 无
非 Copyleft 		✓ 允许 — 无 仅署名 / 允许闭源商用
Apache 2.0
署名 + 专利 / 企业友好
 在 MIT 基础上增加明确专利授权条款；衍生作品可闭源，但须保留声明。 无
非 Copyleft 		✓ 允许 ✓ 明确授权 署名 + 专利 / 企业友好
GPL v3
强传染 / 衍生必开源
 强制衍生作品开源并传递授权；含反 Tivo 化条款及明确专利授权。 强
✗ 强制开源 		✗ 禁止 ✓ 含专利条款 强传染 / 衍生必开源
LGPL
弱传染 / 链接闭源可
 库级别 Copyleft；仅"修改库本身"需开源，通过链接方式使用可闭源。 弱
仅修改库须开源 		✓ 允许链接 ✓ 含 弱传染 / 链接闭源可
BSD 3-Clause
署名 + 禁背书 / 近乎公共领域
 比 MIT 多一条"不得使用作者名义背书"；其余约束接近公共领域。 无
非 Copyleft 		✓ 允许 — 无 署名 + 禁背书 / 近乎公共领域
MPL 2.0
文件级 / 库项目推荐
 文件级 Copyleft；仅修改过的文件须开源，适合库与混合项目，可与 GPL 兼容。 中
文件级开源 		✓ 允许 ✓ 含 文件级 / 库项目推荐
