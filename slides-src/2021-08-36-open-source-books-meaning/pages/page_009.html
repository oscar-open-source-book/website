$ ./book-sharing --org 读书分享会的组织
// 核心观点　一个高效的读书分享会需要在 议程 · 角色 · 沉淀 · 迭代 四个维度精心设计；"结构化流程 × 自由讨论" 之间的动态平衡，是决定分享质量的关键杠杆。
# 核心流程 · four_stages
[01] 议程设计
Agenda Design
30min 导读 20min 共读 30min 讨论 
/* 节奏紧凑，避免单向灌输 */
const flow = ["导读",
   "共读", "讨论"];
三段时间配比 3 : 2 : 3，从作者背景介绍到原文精读，最后开放自由讨论，形成 输入→消化→输出 的完整闭环。// 拒绝"PPT念稿式"单向输出
[02] 角色轮换
Role Rotation
主持人 × 1 记录员 × 1 轮流领读 
/* 每期指定不同主持人 */
for (let w = 0; w < weeks; w++) {
  host = roster[w % n];
}
每期指定 不同主持人轮流领读，打破固定分工带来的"舒适区"。// 激发参与者主动思考与表达欲，让每个人都是驱动者。
[03] 会后沉淀
Knowledge Asset
会议纪要 金句卡片 知识资产 
/* 24h 内完成产出 */
output = {
  minutes:   "会议纪要.md",
  quotes:    "金句卡片.md"
}
整理 会议纪要与金句卡片，形成可持续查阅的知识资产。// 让每次分享的价值跨越时间，避免"聊完就忘"。
[04] 反馈迭代
Feedback Loop
评分收集 建议汇总 持续优化 
/* 每期闭环反馈 */
while (active) {
  score = collectFeedback();
  if (score < threshold) optimize();
}
每期结束收集参与者 评分与建议，持续优化分享流程与内容选择。// 形成"做→评→改"的敏捷迭代闭环，越办越好。
# KPI_指标 · key_metrics
⏱
单期时长 80分钟 // 导读 + 共读 + 讨论 = 30 + 20 + 30
🔄
主持人轮换制 1人 / 期 // 每期仅设 1 名领读人，全员参与感 MAX
📄
产出物 · 纪要 + 金句 24h内产出 // 会后 24 小时完成沉淀，知识资产即时入库
